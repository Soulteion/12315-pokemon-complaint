# 12315 投诉助手 · 宝可梦活动缺货

一个给 AI 助手用的技能：把「宝可梦三十周年活动抽签抽到了，按抽中时段到店却发现已经售罄」这件事，整理成一份**能直接提交到全国12315平台的投诉材料**，并且在需要时陪你把表单填完。

不用懂法律，不用会写公文。你只要把经历讲清楚，剩下的它来整理。

---

## 这是干什么用的

**痛点**：抽签机制本身不透明——主办方没提前公布备货数量，你按抽中的时段到场，东西已经没了。想投诉，但打开 12315 网站一看要填十几个字段，投诉内容还要自己写，不知道怎么写才不会被驳回。

**这个技能做的事**：

| 它做 | 它不做 |
|---|---|
| 按清单一次问清事实，帮你理出时间线 | 不会替你想像细节（没有的信息就是「待补充」） |
| 写出客观克制的投诉正文与诉求 | 不会写「恶意欺诈」「要求处罚」这类越位定性 |
| 把内容一一对应到 12315 的每个表单字段 | 不会替你过验证码、实名认证 |
| 列出证据清单，告诉你每样证据怎么取证 | 不会未经你确认就点提交 |
| 可选：在浏览器里陪你逐字段填表 | 不会把投诉写成举报，混在一起会被分开处理 |

### 方式一：直接把情况说给 AI 听（最常用）

不用记任何命令，触发词命中就会自动生效：

> 帮我在12315投诉宝可梦，三十周年活动抽签抽到下午的时段，到店想买的已经没货了。

会先反过来问你几件事（活动全称、门店、抽中时段、目标商品、有没有联系过客服、你想要什么结果），**不会瞎编**。

### 方式二：明确点名技能

有些宿主支持直接指定：

> 用 12315-pokemon-complaint 技能帮我整理投诉材料

### 方式三：只想要材料，不提交

> 抽签截图和现场照片我都有，先帮我把投诉材料整理出来，别提交。

会输出完整准备包，然后停在提交前等你。

### 方式四：想让人陪着填表

> 打开12315帮我填投诉，填完让我确认再提交。

它会打开 www.12315.cn 逐字段填、逐字段跟你核对，到提交按钮前停下、把整页念给你确认。**登录、验证码、实名认证这三步永远是你自己做。**

## 你能拿到什么

一份「投诉准备包」，六件套：

1. **事实时间线** —— 每个日期都能在证据里找到对应
2. **投诉内容正文** —— 简洁版（约 300 字）或详细版，直接粘进表单
3. **诉求内容** —— 从措辞库里挑 1–3 条具体、可执行的
4. **表单字段映射表** —— 12315 每个字段分别填什么
5. **证据清单** —— 含每样证据的取证要点和遮挡个人信息提醒
6. **提交前检查表** —— 九项逐条过一遍再交

---

## 三个必须知道的边界

**1. 不编造事实。** 货品数量、损失金额、「已联系客服未解决」这些话，只用你确认过的信息。虚假材料是不予受理情形之一，而你是实名提交的。

**2. 不代过验证环节。** 图形验证码、短信验证码、实名认证（支付宝/微信/扫脸，结果含姓名与身份证号）、支付信息，一律你本人操作。技能到这里会停下说明在等什么，不会索取验证码。

**3. 提交前必须你明确说「提交」。** 会先展示完整预览，你不点头就不点。

另外两条值得提前知道：

- **投诉和举报是两件事。** 投诉＝请求市场监管部门就消费争议组织调解；想「查处、处罚」得另走「我要举报」，一事一单。混着写会被分别处理。
- **没有付款记录要如实说。** 如果你最终没买、也没有任何付款记录，平台可能以「不能证明存在消费者权益争议」不予受理——如实填写，别为了显得更严重而虚构订单。

## 安装

仓库根目录就是技能目录。把整个目录复制（或 clone）到宿主的技能路径即可：

| 作用范围 | 目标路径示例 |
|---|---|
| MiMo Desktop / MiMoCode（用户级） | `~/.config/mimocode/skills/12315-pokemon-complaint/` |
| Claude Code（用户级） | `~/.claude/skills/12315-pokemon-complaint/` |
| Workbuddy（用户级） | `~/.workbuddy/skills/12315-pokemon-complaint/` |
| 项目级（团队共享） | `<项目根>/.mimocode/skills/` 或对应宿主的项目技能目录 |

```bash
git clone https://github.com/Soulteion/12315-pokemon-complaint.git \
  ~/.config/mimocode/skills/12315-pokemon-complaint
```

或在支持技能市场的宿主里直接搜索 `12315-pokemon-complaint` 安装。

> 仓库保留 `README.md` 是为了 GitHub 可读性；技能本体只依赖 `SKILL.md` 与 `references/`。若宿主校验器禁止 skill 目录内出现 README，安装时去掉它即可，不影响触发与执行。

## 修改后怎么验证

`references/test-prompts.md` 里有三条回归用例（直接请求投诉 / 有证据但不提交 / 浏览器协助后确认提交）和四条附加检查项。改完技能按那三条提示词各跑一遍。

结构校验用 skill-creator 自带脚本（路径随宿主安装位置变化）：

```bash
python <skill-creator目录>/scripts/validate_skill.py ./12315-pokemon-complaint
```

期望：无 ERROR。若校验器因仓库根目录存在 `README.md` 报 ERROR，属公开仓库与安装纯度的已知取舍——技能执行不依赖 README；其余 ERROR 必须修掉。
